# Markdown diagnostics

System Settings > Developer contains three separate checks:

- **Project Compatibility** exercises generated archive layouts through the production artifact and source discovery services. An optional local acceptance archive can be configured for real-project acceptance; fast tests do not require M2LB.zip.
- **Content Integrity** compares generated Markdown bytes with the canonical archive reader's temporary decoded artifact representation, records raw/canonical SHA-256 and size/line metrics, and checks that the shared tokenizer and role-specific Explorer extractor complete. It does not insert those artifacts into the current shared repository. A canonical match with different raw bytes is reported as normalized-equivalent (Partial), not as truncation. When `ProjectCompatibility:AcceptanceArchivePath` is configured, raw bytes are captured by the canonical archive reader and compared with its decoded document content.
- **Explorer Text Coverage** runs each production role parser/extractor against generated documents and records separate Source, Parser, Extractor, Page Model, and Render evidence for each source block. Block IDs combine role, canonical artifact fingerprint, line range, and block fingerprint, so repeated identical paragraphs remain distinct. Unprojected authored blocks are retained in the shared keyboard-expandable **Source notes and unmapped text** component with stable `data-source-block-id` hooks. Each loaded Explorer host exposes the parser's canonical document fingerprint as `data-birknext-document-id`; this opaque identity contains no source text or path. Supported structured projections expose their existing deterministic `ProjectionId` and safe kind on the actual Explorer DOM element using `data-birknext-projection-id` and `data-birknext-projection-kind`. The browser verifier first confirms exact document identity, then compares projection IDs, reports missing, duplicate, and unexpected identities, and attaches evidence to the existing source-block result. A missing or mismatched document identity remains `NotVerified` and cannot produce `RenderMissing`. Page Model Verified does not imply Render Verified. The ordinary backend diagnostic does not launch a browser; without browser evidence Render remains `NotVerified`. Direct blocks remain `NotVerified` unless a block-level DOM identity is included in the verification. Decorative table and horizontal separators have the explicit `markdown.decorative-separator` ignore rule.

All diagnostics use generated in-memory data unless the optional configured acceptance archive is explicitly available. Candidate coverage runs independently without selecting artifact authority; previews from configured local archives are suppressed. Diagnostics do not import a project or change workspace artifacts, artifact authority, Source Analysis snapshots, Target Environments, or saved review results. They do not create a project quality score. Generated automated tests are the CI source of truth. Real M2LB acceptance is optional and is reported as NotRun when no configured fixture is available.

Explorer Text Coverage does not require every Markdown character to be rendered literally. A supported block must be represented structurally, visible as authored in an Explorer source note, or covered by a specific ignore/unsupported reason. Anything else is Missing. Source-note previews can be expanded to read the complete source text; long lines wrap and do not require horizontal scrolling. Browser startup, navigation, artifact selection, and other execution failures remain `NotVerified`; `Render Missing` means the browser completed on the correct loaded Explorer route and did not find an expected projection ID. Duplicate expected IDs are reported as render-integrity evidence, and unexpected DOM IDs are retained separately. Constitution's relationship map intentionally renders one logical rule under each parent that references it; repeated ProjectionIds confined to those map nodes describe those distinct graph edges and are not mistaken for missing projections.
