# Markdown diagnostics

System Settings > Developer contains three separate checks:

- **Project Compatibility** exercises generated archive layouts through the production artifact and source discovery services. An optional local acceptance archive can be configured for real-project acceptance; fast tests do not require M2LB.zip.
- **Content Integrity** compares generated Markdown bytes with the canonical archive reader's temporary decoded artifact representation, records raw/canonical SHA-256 and size/line metrics, and checks that the shared tokenizer and role-specific Explorer extractor complete. It does not insert those artifacts into the current shared repository. A canonical match with different raw bytes is reported as normalized-equivalent (Partial), not as truncation. When `ProjectCompatibility:AcceptanceArchivePath` is configured, raw bytes are captured by the canonical archive reader and compared with its decoded document content.
- **Explorer Text Coverage** runs each production role parser/extractor against generated documents and records separate Source, Parser, Extractor, Page Model, and Render evidence for each source block. Block IDs combine role, canonical artifact fingerprint, line range, and block fingerprint, so repeated identical paragraphs remain distinct. Unprojected authored blocks are retained in the shared keyboard-expandable **Source notes and unmapped text** component with stable `data-source-block-id` hooks. The note builder uses explicit projection source ranges; it does not infer coverage from serialized model text. This gives every unprojected source block a full-text destination without inventing a structured Explorer entity. Decorative table and horizontal separators have the explicit `markdown.decorative-separator` ignore rule. Structured source ranges establish Extractor and Page Model evidence only: role-specific component DOM is not yet mapped block-by-block, so Render remains `NotVerified` and the document/run remains Partial rather than claiming end-to-end Pass.

All diagnostics use generated in-memory data unless the optional configured acceptance archive is explicitly available. Candidate coverage runs independently without selecting artifact authority; previews from configured local archives are suppressed. Diagnostics do not import a project or change workspace artifacts, artifact authority, Source Analysis snapshots, Target Environments, or saved review results. They do not create a project quality score. Generated automated tests are the CI source of truth. Real M2LB acceptance is optional and is reported as NotRun when no configured fixture is available.

Explorer Text Coverage does not require every Markdown character to be rendered literally. A supported block must be represented structurally, visible as authored in an Explorer source note, or covered by a specific ignore/unsupported reason. Anything else is Missing. Source-note previews can be expanded to read the complete source text; long lines wrap and do not require horizontal scrolling. Structured Render provenance remains explicitly unverified on a per-block basis and keeps the diagnostic Partial until the structured Explorer nodes expose matching provenance in rendered output.
