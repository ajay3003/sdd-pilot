## B. Defects found and fixed
1. **Execution outside Testplaner.** Planlegg offered a case-level «Start test».
   - **Fixed:** with BirkNext execution on, it now shows a link «Gjennomføres i Testplaner» to the plan's execution. Earlier runs and Azure DevOps results stay listed, read-only.
2. **«0 av 2 påkrevde» looked final** while 3 relevance decisions were open.
   - **Fixed:** the panel now says «3 relevansvurderinger gjenstår – antallet påkrevde punkter kan endres.» (`ScenarioPreparationEngine.UndecidedText`).
3. **«valgfrie forbedringer»** did not match the «Anbefalt før testing» group. Now «anbefalte forbedringer».
4. **Two primary buttons (Lagre and Godkjenn) side by side.** Now there is one primary per state: Lagre while unsaved, otherwise the review step.

## I–L. Readiness model (audited, correct, unchanged engine)
- **Required:** expected result confirmed, verification method.
- **Relevance not assessed:** test data, trigger, environment/access.
  - Three-way: Påkrevd / Ikke relevant / not assessed.
  - Suggestions are shown as «Foreslått» and are never applied without «Bruk forslagene».
- **Recommended:** an approved test case (`CaseReview` = Optional); it never blocks.
- An undecided item is never counted. «Ikke relevant» is never «Oppfylt».
- Readiness is per scenario (the specification's grouping document) and never requires a case.
- **V5 compactness:** Påkrevde and Relevans stay open; «Anbefalt før testing» and «Ikke relevant» fold away with their count.

## M. Approval vs readiness
Separate. Approval is a case review state (`ReviewAsync`) and is only evidence for the optional criterion. Readiness never sets approval. No execution result is written here.
