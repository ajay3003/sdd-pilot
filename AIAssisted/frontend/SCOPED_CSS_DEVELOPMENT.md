# Scoped CSS Development Setup

## Background

Blazor WASM generates scoped CSS bundles during the build process. The bundle file (`BirkNext.Web.styles.css`) is placed in `obj/Debug/net8.0/scopedcss/bundle/` but needs to be in `wwwroot/` for the dev server to serve it to the browser.

## Problem

When developing locally without the scoped CSS in wwwroot, the browser doesn't receive the stylesheet, resulting in:
- Missing layout styling (no grids, no flexbox)
- UI elements appearing unstyled
- Text appearing concatenated without proper spacing/badges

## Solution

After running `dotnet build`, execute:

```powershell
.\setup-dev-scoped-css.ps1
```

This script copies the generated scoped CSS bundle from the build output to wwwroot, making it available to the dev server.

## Details

- The CSS bundle is automatically generated by Blazor and is correctly configured
- The bundle must NOT be checked into git (it's in `.gitignore`)
- Published builds automatically include the bundle
- Development builds require this manual step to make the bundle available for local development
- The scoped CSS uses Blazor's automatic scope attributes (`[b-xxxxxxxx]`) to isolate styles per component

## Troubleshooting

If styling still doesn't appear after running the script:

1. Ensure the script runs successfully (check for error messages)
2. Clear browser cache (F5 may not be enough; try Ctrl+Shift+Delete)
3. Rebuild the project:
   ```
   dotnet clean BirkNext.Web
   dotnet build BirkNext.Web
   .\setup-dev-scoped-css.ps1
   ```

## Notes for Future Developers

- The `BirkNext.Web.styles.css` file in wwwroot is generated and should not be manually edited
- If the scoped CSS appears to be missing, this is the likely culprit
- The published build handles this automatically; this is a development-only issue
