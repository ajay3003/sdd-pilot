# Scoped CSS Development Setup

## Background

Blazor WASM generates scoped CSS bundles during the build process. These bundles contain styled component rules with automatic scope attributes (e.g., `[b-p49ij5k7ni]`) that isolate CSS per component.

The bundle is generated in: `obj/Debug/net8.0/scopedcss/bundle/BirkNext.Web.styles.css`

For the development server to serve these styles to the browser, the bundle must be in `wwwroot/`.

## Normal Development Workflow

### Recommended: Use the dev-build wrapper

Instead of running `dotnet build` directly, use the provided `dev-build.ps1` script:

```powershell
# Build Debug (default) and setup CSS automatically
.\dev-build.ps1

# Build Release
.\dev-build.ps1 -Configuration Release

# Build, setup CSS, and run tests
.\dev-build.ps1 -Test

# Clean and rebuild
.\dev-build.ps1 -Clean
```

The script automatically:
- Builds the project
- Copies the scoped CSS to wwwroot for Debug builds
- Runs tests if requested
- Cleans up development CSS before Release builds

### Manual Alternative

If you prefer to use `dotnet build` directly:

```powershell
# Build the project
dotnet build BirkNext.Web -c Debug

# Setup the scoped CSS
.\setup-dev-scoped-css.ps1
```

## Visual Symptom of Missing CSS

If the scoped CSS is not available, Task Explorer Map View will show:
- No grid layout (text stacks vertically)
- Concatenated badge text like "CompleteParallel" instead of separate badges
- Missing styling on task titles, phase cards, and group counts

The HTML structure is correct; the CSS just isn't being applied.

## For Release Builds

Release builds use Blazor's standard static-web-assets pipeline and don't need special handling.

If switching from Debug to Release locally:
```powershell
.\dev-build.ps1 -Configuration Release -Clean
```

The `-Clean` flag removes the development CSS file that may interfere with Release builds.

## Technical Details

- The scoped CSS bundle is automatically generated by Blazor and is correctly configured
- The bundle file (`BirkNext.Web.styles.css`) must NOT be checked into git (it's in `.gitignore`)
- Published/Release builds use Blazor's standard bundling and don't require this setup
- Development builds need the bundle copied to wwwroot so the dev server can serve it
- Each component's CSS is scoped with a unique attribute like `[b-p49ij5k7ni]` to prevent style leakage

## Troubleshooting

### Styles aren't appearing after build

1. Verify the CSS file was copied:
   ```powershell
   ls BirkNext.Web/wwwroot/BirkNext.Web.styles.css
   ```

2. If missing, run the setup script:
   ```powershell
   .\setup-dev-scoped-css.ps1
   ```

3. Clear browser cache (Ctrl+Shift+Delete)

### Build fails with static assets error

This can happen when switching between Debug and Release builds without cleaning. Run:

```powershell
.\dev-build.ps1 -Clean
```

This cleans the project and removes the development CSS file.

### Manual CSS Setup

If the scripts don't work for any reason, you can manually copy the CSS:

```powershell
Copy-Item BirkNext.Web\obj\Debug\net8.0\scopedcss\bundle\BirkNext.Web.styles.css `
          BirkNext.Web\wwwroot\BirkNext.Web.styles.css -Force
```

## Notes

- The `BirkNext.Web.styles.css` file in wwwroot is machine-generated and should not be manually edited
- Each developer gets their own copy; this is not shared via git
- The published build includes the scoped CSS automatically via Blazor's standard mechanism
