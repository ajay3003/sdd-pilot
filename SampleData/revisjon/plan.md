# Implementation Plan: M2LB.Revisjon M01 — Receiving and storing leselogg events

**Branch**: `001-M2LB.Revisjon-m01` | **Date**: 2026-04-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-M2LB.Revisjon-m01/spec.md`

## Summary

M2LB.Revisjon M01 is a .NET 10 Worker Service (hosted as a minimal web app for Kestrel
support) that continuously consumes `LeseloggHendelse` messages from Azure Service Bus queue
`leselogg` using Wolverine, and writes each event as an immutable JSON file to Azure Blob
Storage (WORM) at path `{year}/{month}/{day}/{hendelsesId}.json` where the date is derived from
`HendelsesTidspunkt` normalised to UTC. Idempotency is enforced via `IfNoneMatch: *` (HTTP 412
= already stored = success). In-process retry with exponential backoff handles transient Blob
Storage failures; exhausted messages are abandoned to Service Bus for redelivery up to
`MaxDeliveryCount` (10), after which Service Bus routes to DLQ. A `GET /health` endpoint probes
both dependencies. No SQL database. No transformation of event content.

## Technical Context

**Language/Version**: .NET 10 / C# 13  
**Primary Dependencies**: Wolverine + Wolverine.AzureServiceBus (consumption, retry policy),
Azure.Storage.Blobs (WORM writes via `IfNoneMatch: *`), Azure.Messaging.ServiceBus (health probe
via `ServiceBusAdministrationClient`), ASP.NET Core minimal API (Kestrel + health checks)  
**Storage**: Azure Immutable Blob Storage — WORM, single container, no SQL  
**Testing**: xUnit + Shouldly; Azurite (Blob emulator via `Testcontainers.Azurite` NuGet package);
Azure Service Bus emulator (via generic `Testcontainers` `ContainerBuilder` with SQL Server sidecar
on a shared Docker network + embedded `servicebus-config.json` test resource); integration tests
start their own containers automatically — no external infrastructure required to run `dotnet test`;
felles-compose is for running the service locally, not for test execution  
**Target Platform**: Azure App Service (Linux), .zip deploy; Norway East region; Always-On required  
**Project Type**: .NET minimal web app (`WebApplication.CreateBuilder`) acting as a Worker Service
— Wolverine drives message consumption; Kestrel serves only `GET /health`  
**Performance Goals**: Hundreds of events/day, occasional bursts to a few thousand — no strict
latency SLA; single instance sufficient for M01  
**Constraints**: No SQL (FR-011); Managed Identity only in production (FR-010); Always-On on App
Service (FR-001); WORM — no delete/update operations possible (Principle I); Norway East (FR-012)  
**Scale/Scope**: Stateless — scales horizontally without code changes; single instance for M01

## Key Design Decisions

### Message Handler (LeseloggHendelseHandler)

```
ServiceBusMessage arrives
    └─ Wolverine deserialises → LeseloggHendelse + Envelope (raw bytes)
           └─ Set KorrelasjonId scope on ILogger
           └─ Validate: deserialization succeeded (Wolverine handles failed deserialization → DLQ)
           └─ Compute BlobPath.Compute(hendelse)
           └─ Call IBlobLeseLoggCreator.WriteAsync(path, envelope.Data)
                  ├─ Returns true  → log processed, Wolverine completes message
                  └─ Returns false → log duplicate (idempotent), Wolverine completes message
           └─ On RequestFailedException (transient): propagate → Wolverine retry policy kicks in
```

Wolverine retry policy (configured in `Program.cs`):
- Retries: up to 4 in-process attempts with exponential backoff: 100ms, 500ms, 2s, 10s
- Applies to: `RequestFailedException` where `Status` is 5xx or 429 (transient)
- HTTP 412: caught in handler, never reaches Wolverine retry
- After exhausting retries: Wolverine abandons the SB message → SB redelivers (MaxDeliveryCount=10) → SB DLQ

### Raw Bytes Preservation (FR-004)

`Envelope.Data` in Wolverine contains the raw serialized bytes from the Service Bus message.
These bytes are passed directly to `IBlobLeseLoggCreator.WriteAsync` without round-tripping through
the deserialized object. This guarantees byte-level identity with the received event.

If `Envelope.Data` is not available in a specific Wolverine version, fall back to:
`System.Text.Json.JsonSerializer.SerializeToUtf8Bytes(hendelse, JsonOptions.Camel)` with
`JsonSerializerDefaults.Web` — semantically identical to the input format.

### Health Check Response Mapping

```
HealthStatus.Healthy   → "Healthy"
HealthStatus.Degraded  → "Unhealthy"   (individual check)
HealthStatus.Unhealthy → "Unhealthy"   (individual check)

Top-level "status": "Healthy" if all checks Healthy; "Degraded" otherwise
HTTP status: 200 for Healthy/Degraded; 503 for service unavailable
```

### Authentication Strategy

| Environment | Service Bus | Blob Storage |
|---|---|---|
| Local dev | Connection string (`appsettings.Development.json`) | Connection string (Azurite) |
| Production | `DefaultAzureCredential` (Managed Identity) | `DefaultAzureCredential` (Managed Identity) |

`DefaultAzureCredential` tries Managed Identity first on App Service — no code change needed
between local and production beyond configuration.
