# BirkNext — Automatic contract test data generation: implementation (2026-11-10)

Branch `008-traceability-first`. Baseline `d2746018`. Commits: `0ed74d1f` (generator, service, retention, suite integration, UI) and the
follow-up commit with the acceptance fixes and these reports.

## Workflow

Import contract → parse → operations → **Generate Tests** → test definitions *and* typed synthetic data → validated by the contract validator
→ kept in Test Data → approved and pinned automatically **only when certain** → readiness → explicit, authorised execution.
The only things left for a human: missing domain information (identifiers of existing records, identities, Kode 6/7 persons), values the
generator cannot satisfy (patterns, conflicting bounds, custom scalars), and environment access (target, authentication).

## Architecture (no new engine, no new store)

| Part | Where | Role |
|---|---|---|
| `ContractTestDataRules` | `Services/ContractTesting` | pure, deterministic value derivation per test input |
| `ContractTestDataService` | `Services/ContractTesting` | validate (contract validator), persist (Test Data), approve (Test Data's approval rule), bind (`ContractTestService.BindAsync`) |
| `POST api/contract-testing/contracts/{key}/test-data` | `ContractTestingController` (configuration-write policy) | entry point; never sends a request |
| `source_contract_documents` | `IqrSourceStore` (snapshot save) + `ContractRegistryService.ImportFromSourceAsync` | retained OpenAPI/GraphQL texts → full schema validation of source-imported contracts |
| `TestDataCatalogService.Approve(registry, asset, version, now)` | Test Data | the one approval rule, shared |
| Integration Suite Generator | `IntegrationSuiteService` | uses the same service; its own synthesizer was removed |
| UI | Contract Testing → Generate tests / Generate test data; suite Test data tab | per-operation state, provenance per value, only what needs a human expanded |

## Supported schema constructs

JSON Schema (when the document text exists): local `$ref` (via the validator), `allOf` (merged), `oneOf`/`anyOf` (first non-null alternative; the
validator then checks exactly-one/any), `const`, `enum`, `default`, `type` (3.0 string, 3.1 arrays incl. `null`), `format` date, date-time, time,
uuid, email, uri/url, hostname, ipv4, byte; `minimum`/`maximum`, `exclusiveMinimum`/`exclusiveMaximum` (3.0 boolean and 3.1 number), `multipleOf`,
`minLength`/`maxLength`, `pattern` (value checked with a bounded regex; simple anchored forms `^\d{n}$`, `^[0-9]{n}$`, `^[A-Z]{n}$`, `^[a-z]{n}$`,
`^[A-Za-z0-9]{n}$` generated), arrays with `minItems`/`maxItems`/`uniqueItems` (≤ 20 items), objects (required always; optional only when
certain), `readOnly` (never sent). Depth ≤ 6, ≤ 40 properties.
Typed contract model (source-backed version without text): types incl. `type:format`, named object types, enums, arrays, required.
GraphQL: `String`, `Int` (number), `Float`, `Boolean`, `ID` (uuid, needs review), enums, input objects, lists, non-null; custom scalars UUID/Date/
DateTime/Long/Decimal/…; other custom scalars are Unresolved ("map it or provide a value").

**Not supported** (diagnostic, never claimed): `binary`, `password`, other formats (value proposed, needs review), `not`, `if/then/else`,
`patternProperties`, external `$ref` (validator reports), complex regex patterns (needs review), recursive schemas beyond depth 6.

## Certainty and provenance

Each value: `Origin` = ContractConstraint (enum, const) · SchemaDefault · SyntheticRule · ExistingTestData · ReviewedUserValue; `Certainty` =
Certain · NeedsReview · Unresolved; the rule used; the reason. Never generated (Unresolved): identities (fødselsnummer, D-number, DUF, BirkId, …),
any 11-digit value (identity-shaped, whatever the field is called), credentials (aligned with Test Data's rule), Kode 6/7 / protection
classifications. Needs review: path parameters and record identifiers (`…Id`, `…nr`, GraphQL `ID`), unsatisfied patterns, unknown formats.
Examples in a contract are never copied.

## Persistence, approval, binding

Alias `gen-{contract}-v{version}-{operation}`; created once; never overwritten. A tester's later version is used as reviewed values (and their
approval kept). A set differing from what the generator proposes now is kept and flagged. Automatic approval only when: generated by Contract
Testing, every required value Certain, the materialized request **Valid** (contract validator) and nothing unsupported. Binding only of tests
without a binding (a tester's binding is never replaced); negatives share the positive's set. A newer contract version is never rebound silently
(tests move only through the reviewed update proposal).
