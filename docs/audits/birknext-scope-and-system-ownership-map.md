## Identity rules for proposed consolidation

Use the repository/project identity plus source snapshot identity for discovered candidates. Logical system IDs must be project-local unless an explicit shared-system concept is introduced with tenant/security rules. Do not correlate systems solely by label. Store endpoint/deployment binding as `(logical system id, environment id, endpoint/config reference)` and keep secret values out of the registry. Scope identity must be `(project id, scope id, revision)`; membership references preserve entity/artifact identity and provenance. An asset association is a reference to immutable TestDataAssetId/revision policy, never copied payload. Historical run evidence must pin its scope revision and chosen asset versions.
